# xFalcon Desktop v0.5.19

Changes since v0.5.18:

- A response running in xFalcon Web is no longer stopped when you open or refresh the desktop app. The desktop used to treat any answer in progress that it was not itself producing as leftover from a crash and cancel it, which ended a reply that was still being written in the browser.
- A response running elsewhere also no longer shows this window a recovery notice about an interruption that did not happen, and no longer leaves the message box waiting on an answer it cannot receive. The desktop shows the conversation as idle and picks up the finished reply the next time it reloads that conversation.
- The Stop button now shows that it is working as soon as it is pressed, instead of looking untouched until the response ends. Stopping can take a moment when the response was started elsewhere.
- If stopping fails, the Stop button comes back so it can be pressed again, and the reason is shown.

Known limits:

- This release stops the desktop from interfering with a response running in the browser. It does not yet show that response as it is written. A reply started in xFalcon Web appears in the desktop once it has finished and the conversation is reopened.
