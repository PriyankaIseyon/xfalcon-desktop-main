# xFalcon Desktop v0.5.22

Changes since v0.5.21:

Project reports

- In a chat that belongs to a project, "Save to project" saves a dashboard as
  an HTML file in the project's own `reports` folder on your computer, instead
  of in your saved reports on the server. Chats outside a project save to the
  server, as before.
- Saving never overwrites a file. A name that is taken gets a number, like
  `Q3 revenue (2).html`, and saving the same dashboard twice offers to open the
  copy you already have.
- After a save, "Open file" shows the report in the project's files.

Project files

- Files open by type, the way the chat shows them: HTML dashboards as a live
  preview, SVG as an image, Markdown as formatted text, CSV, TSV, JSON and
  JSON Lines as tables, and SQL, Python and other code highlighted. Other files
  open as plain text.
- Large files open. Files up to 64 MB load whole and scroll smoothly at any
  length. Larger ones, up to 10 GB, open a page at a time. Large CSV and TSV
  files page through their rows, and you can jump to a row.
- You can edit files up to 16 MB (previously 1 MB), and save a project report
  up to 64 MB.
- Folders open by default, with guide lines that show what sits inside what.
  One button beside the filter collapses or expands them all. Dependency and
  build folders such as `node_modules` stay closed.
- Each file shows a small colored tag for its type, such as `CSV`, `HTML` or
  `SQL`. Very long names are shortened in the middle, and hovering shows the
  full name.
- A file's actions (Copy, Show source, Open in panel, Reload file, Edit) sit in
  one row that stays in place while the file scrolls.
- File, History & Revisions and Schemas are tabs side by side. Schemas show
  each column's type in color, as the dataset upload does.
- The mouse wheel scrolls wide tables and code again. It used to stop over a
  table wider than the window.
- Folders with up to 100,000 entries list. The limit was 10,000.

The agent

- Tool results the agent reads now scale with the model: about 5% of its
  context window, from 32 KB up to 256 KB. A 1M-token model sees about 200 KB
  of each result, up from 32 KB. When a result is larger, the agent sees as
  much as fits and exactly what was left out.
- File reads and folder listings come in pages that fit, so the agent can go
  through a large file or folder step by step.
- A request the agent makes that is too large gets an answer it can act on.
  It used to end the run.
- Longer answers are kept (up to 512 KB).

Look and feel

- Buttons share one style everywhere: file views, chat cards and the side
  panel.
- The main menu and tabs show the current one as a raised pill on a darker
  track, as the web app does.
- "All files" in a project's sidebar list is now "Browse files", with a folder
  icon, so it no longer looks like a chat.

Known limits

- The agent's larger results need the matching server update. Until it is
  deployed, a long-context model's result over 32 KB may fail to save.
- Files over 64 MB open read-only, and their pages show byte positions rather
  than line numbers.
- Project folders inside WSL (`\\wsl.localhost\...`) can't be listed from the
  Windows app. Use a Windows folder.
