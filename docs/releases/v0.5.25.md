# xFalcon Desktop v0.5.25

Changes since v0.5.24:

Project files

- When you ask xFalcon to create or update a file in a project, it writes it
  directly. The "Review file changes" window is gone, along with its Apply and
  Discard buttons, which could stop responding after a run ended.
- Before any file is changed, deleted, or replaced by a rename, its earlier
  version is kept under History & Revisions. Restoring a revision of a deleted
  file brings it back.
- Deleting or replacing a file larger than 64 MiB is refused, because no copy of
  it can be kept.
- The notice shown when you trust a folder now says that xFalcon writes there
  without asking, and where earlier versions are kept.

Schemas

- A file's name appears once. The path shows only when it adds something, such
  as a SQLite table or a file in a subfolder.
- A cleaner layout: one summary line per table, a flush column list, and sample
  values as chips, without repeats.

Fixes

- In the Split diff view, long lines wrap within their own side instead of
  running into the other.
