# xFalcon Desktop v0.5.29

Changes since v0.5.28:

Private models

- Adding a private model now asks only for the endpoint URL and your API key.
  The endpoint is filled in for you. The model name, context size, output limit,
  tool use and image input are set automatically for the company model, so they
  are the same for everyone. Models you already added are brought in line the
  next time the list loads.
- The company model now has the time it needs. A single request may wait in the
  gateway's queue and think for several minutes, so requests may run for up to
  an hour and a run for up to two hours without being stopped as stalled.
- The app sends one request at a time to the company model. When the gateway is
  busy or briefly unreachable it retries after 30, 60 and 120 seconds. It does
  not retry a request that timed out.
- Chat titles, follow-up suggestions and conversation summaries finish in
  seconds instead of waiting on the model's long thinking step.

Chat

- Fixed "the complete conversation exceeds this model's safe context capacity"
  appearing on short chats with a private model. The model had been added with
  too little room for the app's own instructions. Private models now start with
  room for long agent runs.
- A conversation that is too long for a local or private model is no longer
  refused when summarizing does not help. The app shortens it itself, newest
  content last, and tells the model what was cut. You no longer see a context
  or capacity error for a conversation that can be made to fit.
- A model response that is cut off by the connection, whether it closes or
  resets after output began, is now continued in smaller pieces, as an output
  limit is, instead of ending the run with an error.
- When the company gateway closes a streamed reply early, the app asks again
  without showing anything, and for the next 15 minutes asks the gateway for
  whole replies instead of streamed ones. A reply cut before any answer text is
  repeated up to eight times before the run gives up.
- On the company gateway, the model thinks about a new message but not again
  after every tool result. A run of fourteen tool calls took eleven minutes with
  thinking after each; it now takes four to six.
- A single turn that reads many large results at once, such as fourteen pages
  requested together, is shortened to fit the model's window instead of being
  refused.
- Stopping a run, mid-answer or between tool calls, is tested live for the
  company model, Luna and Sonnet.
- Long conversations are condensed more reliably for every model. A long run that
  followed an earlier summary can now be condensed again instead of stopping at
  the context limit.
- One busy or failed summary request no longer turns condensing off for the rest
  of the run.
- A native-compaction run for Claude no longer fails with "durable context
  history cannot form a compaction boundary" when the run's own unsaved turns
  follow a very long saved history.
- A model response that ends without the closing marker, after it has already
  finished, is now accepted. This also helps Grok, Luna and Sol.
- Several tool calls requested at once by a local or private model are kept
  apart even when the server leaves out, or repeats, their position numbers.
- Chat titles are read even when the model wraps them in a code block.
- The retry button now also appears when a private model's endpoint cannot be
  reached.
- Removed a hint that told you to raise a model's output limit in Settings,
  which is no longer possible there.
- A provider error that only mentions tokens or a context window, such as a
  rate limit, is no longer mistaken for an over-long conversation. It no longer
  shrinks the room the app allows itself.

Known limits

- Private models other than the company model cannot have their name or limits
  edited in the app. A new private model always uses the company model's name.
- A request rejected after the gateway's one-hour limit is reported as the
  provider being temporarily unavailable.
