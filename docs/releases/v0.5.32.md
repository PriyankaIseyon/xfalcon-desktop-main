# xFalcon Desktop v0.5.32

Changes since v0.5.31:

- Multi-file project work keeps running while the model streams, builds file-edit
  arguments, executes tools, or compacts context. Healthy work no longer hits the
  inactivity watchdog because progress took a different callback path.
- Project workflows have room for 256 tool rounds and 2,048 calls over one hour.
  Paging the same read tool shares that allowance. Each tool has two minutes to
  finish, and parallel execution stays capped at eight calls.
- Partial tool arguments and opaque progress stay hidden. A transient failure
  before usable output can retry safely. A complete tool call or visible output
  still prevents retry, so an edit cannot be executed twice by that retry path.
- The model instructions require completing and verifying every requested file
  read and edit before giving the final answer. Existing file permissions,
  approvals, atomic writes, context limits, and Stop handling remain enforced.
