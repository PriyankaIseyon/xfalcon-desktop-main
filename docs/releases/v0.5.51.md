# xFalcon Desktop v0.5.51

Changes since v0.5.50:

## MCP selection in chat

- **Choose the MCP server beside the model in the composer.** All servers remains the default. Select one server to restrict that chat's MCP tools to that connection.
- **Changing the selection starts a fresh chat.** The previous chat stays in your history. Its messages, summaries, draft, attachments and project context are not carried into the new chat.
- **A selected chat keeps its server binding.** Reopening, retrying, editing and regenerating use the same server ID and endpoint. If the server is removed, unavailable or points to a different endpoint, the app stops the request. It does not substitute another MCP connection. Tool history and saved summaries are checked against the selected scope before a model request.

## Sign-in setup

An added server still needs its own OAuth registration. Its Casdoor application must allow `http://127.0.0.1:19848/callback`. This release does not change Casdoor registrations. The staging `ida-mcp-iseyon` application rejected that callback during release preparation; an application administrator must update its allowlist before that connection can sign in.
