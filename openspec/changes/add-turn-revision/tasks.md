## 1. The DA client learns to cut

from_message_id) -> Result<TruncateResult, DaChatApiError>` posting
      `/api/v1/chat/conversations/{id}:truncate`. The request and result types
      are already generated; only the session method is missing. Map 404 to
      `NotFound` and 401/403 to `Unauthorized`, as the sibling methods do.
- [x] 1.2 A test that the method is shaped like its siblings: an error status
      maps to the typed error and not to `InvalidResponse`.

## 2. A submission can revise

- [x] 2.1 `chat/service.rs`: `enum TurnRevision { None, Replace { cutoff },
Rerun { cutoff } }` with `writes_user_message` and `cutoff` derived from
      it, so the two facts cannot drift.
- [x] 2.2 `message_send_inner` takes the revision. The cut goes AFTER the
      credential/model/conversation resolve and BEFORE
      `create_user_message_idempotent`, so a submission that cannot run fails
      with the conversation intact.
- [x] 2.3 `Rerun` skips `create_user_message_idempotent`. The run still records
      the prompt as its `input_message`.
- [x] 2.4 Cancel every active run of the conversation this process owns before
      the cut — ids from the reconciled snapshot via `wire::is_active_run`,
      tokens from `run_cancels`.
- [x] 2.5 Purge the journal of every run id present before the cut and absent
      after it (`Journal::purge_run`).
- [x] 2.6 `message_edit(app, conversation_id, message_id, text)`: resolve the id
      in the reconciled snapshot, require role `user`, submit `Replace`.
- [x] 2.7 `message_regenerate(app, conversation_id, message_id)` REWRITTEN:
      resolve the id, walk back to the nearest preceding `user` turn, submit
      `Rerun` with that turn's text and the message after it as the cutoff. The
      old body — re-send the last user text through `message_send` — is deleted,
      not kept.
- [x] 2.8 `message_send` keeps its `send_in_flight` guard and both revisions go
      through it.

## 5. The store cuts optimistically

- [x] 5.1 `chatStore`: `beginTurnRevision(cutoffMessageId)` removes the cutoff row
      and everything after it, retires the live run state that belonged to the cut
      tail, and returns a restore value; `rollbackTurnRevision(restore)` puts it
      all back. A `revising` field drives the indicator from the click frame.
- [x] 5.2 `useTranscript` exposes `revising`; `ChatPane` reads
      `pending || revising` for the thinking indicator, so the pill is on screen
      before the command resolves.
- [x] 5.3 `resetChatStore` and `beginNewConversation` clear `revising` and any
      open edit.
