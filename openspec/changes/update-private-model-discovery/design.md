## Decisions

- Support hosted public HTTPS APIs using OpenAI Chat Completions and bearer keys, consistent with the existing private adapter. Preserve the supplied API base path; append `/models` without guessing a version or probing other hosts.
- Discovery is a read operation. It does not save keys or run inference. Reuse public-address validation, DNS pinning, TLS verification, disabled redirects, response bounds, and a short timeout.
- Keep authentication and address refusal distinct from optional discovery failure. A missing, empty, malformed, or unreachable catalog permits manual entry with a specific notice.
- Preserve exact model IDs and provider prefixes. Never infer a prefix from a model's display name.
- Parse documented optional metadata and preserve reported values exactly. Fill missing settings with clearly labeled xFalcon suggestions: 32,768 context tokens, 4,096 output tokens, Temperature 0.7, and Top P 0.9. When only one token limit is reported, fit the missing suggestion alongside it. Do not infer capacity or capabilities from a model name; unsupported sampling remains empty and omitted. Existing saved values are not replaced by suggestions.
- Use the backend's canonical 16,384-token reserve and 128,000-token per-turn output cap in generated frontend contracts. Validate raw output below context and context above capped output plus reserve. Preserve reported ceilings rather than applying an arbitrary 10% reduction: runtime admission already reserves overhead. Show token-field integer bounds and sampling ranges in the form.
- Show invalid prefilled token limits immediately. Clear save/discovery errors on user corrections and offer explicit dismissal. Keep the retry key field visible through corrections so clearing an error cannot remove it while the user types. Retain synchronous busy guards and invalidate async results on close, reopen, and account changes.
- Omit unset sampling values on the wire so provider defaults apply. Save explicit sampling overrides in account-owned device storage because DA does not expose sampling fields. A local write failure is an explicit failure, including when DA may already have committed the model mutation.
- Scope company Qwen transport tuning to the host and exact Qwen model ID. Other models on the same gateway retain their own route and settings.
- Identify duplicates by normalized API base, exact API key, and exact upstream model ID. Resolve only the existing model's bound key in native code, compare secrets there, and return only model IDs and display names for the current account. The add dialog blocks duplicates before save and names the existing entry. Display labels never affect identity.
- Repeat the duplicate check under the native save lock before inference or mutation, and exclude the current row on updates. A failed preflight is a definite pre-mutation failure that preserves the editor for retry. These Desktop checks do not impose uniqueness across simultaneous saves from separate devices.
- Ignore stale discovery/save results after cancellation, reopening, or an account change. Clear submitted keys on save or actionable failure.
- Test the selected model inside the native create/update command before any DA or local mutation. Use the real provider adapter, selected sampling, and a small bounded greeting with no tools or images. Require nonempty text and successful completion; reject empty, failed, timed-out, or incomplete streams. Bound the whole operation, including DNS and transport wait.
- Retest URL, key, model ID, output-token or sampling changes, and re-enabling. A stored-key retest resolves only this model's bound key, without provider-wide fallback. A changed endpoint requires an explicit replacement key before testing. Display, context-limit, or capability-only edits, disabling, and removal do not run inference. A test failure returns a definite pre-mutation failure so the editor stays open and the catalog remains unchanged.
- Show that the greeting consumes a small number of tokens. A successful greeting proves basic inference access; it does not verify the stated context limit or tool/image capabilities.

## Research

- [OpenAI model objects](https://developers.openai.com/api/reference/resources/models) expose IDs and ownership, without context limits or sampling defaults. Discovery therefore cannot depend on extra metadata.
- [OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create) documents a basic message request, bounded output, and model-dependent parameter support. The connection test uses the app's existing compatible adapter and rejects unsupported configurations before saving.
- [OpenRouter's model catalog](https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties) documents `context_length`, `top_provider.max_completion_tokens`, `architecture.input_modalities`, `supported_parameters`, and `default_parameters`.
- [OpenRouter sampling parameters](https://openrouter.ai/docs/api_reference/parameters) explain that absent sampling values defer to provider defaults. Temperature and Top P have separate ranges; provider support still matters.
- [Ollama OpenAI compatibility](https://docs.ollama.com/api/openai-compatibility) supports `/v1/models` and Chat Completions. Its context size is configured on the server, so the Desktop context field describes that limit rather than changing it.
- [OpenAI conversation-state guidance](https://developers.openai.com/api/docs/guides/conversation-state) defines the context window as input, output, and, for relevant models, reasoning tokens. Capacity should reflect the server's actual ceiling; application headroom belongs in request admission.
- [SGLang's model-card schema](https://github.com/sgl-project/sglang/blob/main/python/sglang/srt/entrypoints/openai/protocol.py) documents optional `max_model_len` on model-list entries.
- [LiteLLM model management](https://docs.litellm.ai/docs/proxy/model_management) exposes richer information on an additional management route. Desktop does not probe management endpoints or require administrator credentials for basic model setup.
